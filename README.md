# maxisi.github.io

Website of Maximiliano Isi's research group (Columbia University / Flatiron Institute), built with
[Jekyll](https://jekyllrb.com) on a customized [al-folio](https://github.com/alshedivat/al-folio) fork
and deployed to GitHub Pages by `.github/workflows/deploy.yml`.

## Editing content

| What | Where |
|---|---|
| Home page text, tagline, portrait | `_pages/about.md` (front matter + body) |
| Research areas (cards on the home page, sections on `/research/`) | one file per area in `_research/` (`title`, `summary`, `img`, `keywords`, `software`, body text) |
| People (`/group/` and the avatar strip on the home page) | `_data/people.yml`; photos go in `assets/img/people/` |
| Teaching (`/teaching/`) | `_data/teaching.yml` |
| News (home page and `/news/`) | one file per item in `_news/` (`layout: post`, `date`, `inline: true`, body) |
| Notes (`/notes/`) | `_posts/`; see below for notebooks |
| Software cards (`/software/` and research pages) | list of `owner/repo` in `_data/repositories.yml` |
| CV (`/cv/`) | `_data/cv.yml` (mirrors `maxisi_cv.tex` in the private `maxisi/cv` repo). The PDF in `assets/pdf/` is pushed here by that repo's GitHub Actions build on every push to its `master` (deploy key `cv PDF publisher`, secret `SITE_DEPLOY_KEY` in `maxisi/cv`); `python3 bin/update_cv.py` copies it by hand instead |
| Contact details, social links, site metadata | `_config.yml` |

### Publications (automatic)

The bibliography in `_bibliography/papers.bib` is synced with INSPIRE every Monday by
`.github/workflows/update-publications.yml`, which runs the scripts in `bin/`:

- `update_inspire_stats.py` refreshes the h-index / paper / citation counts (`_data/inspire_stats.yml`);
- `update_publications.py` adds new papers and refreshes publication details of existing ones, and
  updates the `years:` list in `_pages/publications.md`. Hand-edited fields (`author` with the `*`
  mentee marker, `title`, `abbr`, `preview`, `selected`, `keywords`, …) are never overwritten;
- `update_previews.py` makes a thumbnail from the first figure of each new paper's arXiv source
  (set `preview = {none}` to opt an entry out);
- `update_repos.py` refreshes the software cards (`_data/github_repos.yml`).

Per-paper conventions in the `.bib` file:

- `selected = {true}` shows the paper on the home page;
- `keywords = {ringdown, populations, methods}` (any subset) links the paper to research areas: it
  appears under "Key papers" on `/research/` and in the topic filter on `/publications/`. The values
  must match the `keywords` field of a file in `_research/`;
- `{First Last*}` in `author` marks a mentee.

Run any script with `--dry-run` to see what it would change; the workflow can also be started by hand
from the Actions tab.

### Notes from Jupyter notebooks

Notes are ordinary Markdown posts in `_posts/`. Those converted from GitHub gists are generated by
`bin/import_gists.py` from the list in `_data/gists.yml`:

```bash
python3 bin/import_gists.py            # convert new or updated gists
python3 bin/import_gists.py --only simulate-gw-noise --force
```

The script saves the notebook to `assets/notebooks/`, figures to `assets/img/notes/<slug>/`, and writes
the post with a link back to the gist. Posts that have not changed on GitHub are left alone, so edits
to a generated post survive until the gist itself is updated (or `--force` is used). To add a gist,
append an entry to `_data/gists.yml` and run the script.

## Building locally

The site needs Ruby ≥ 3.1 (macOS ships 2.6). With Homebrew:

```bash
brew install ruby@3.3 imagemagick
export PATH="/opt/homebrew/opt/ruby@3.3/bin:$PATH"
bundle config set --local path vendor/bundle
bundle install
bundle exec jekyll serve --livereload --config _config.yml,_config_dev.yml
```

`_config_dev.yml` turns off image conversion and minification for fast rebuilds; CI does not use it.
Pull requests get a full production build (with `purgecss`) whose output is uploaded as a workflow
artifact named `site`.

## Layout notes

- Pages with `wide: true` in their front matter use the 1100 px container (`max_width_wide` in
  `_config.yml`); everything else uses the 800 px reading measure.
- New components use the `--global-*` CSS variables in `_sass/_themes.scss`, so they follow the
  light/dark toggle automatically. Site-specific styles live in `_sass/_home.scss`, `_sass/_group.scss`
  and `_sass/_notes.scss`.
- Classes toggled from JavaScript must be listed in the `safelist` of `purgecss.config.js`.
